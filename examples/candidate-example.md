# Candidate mode example

**Provenance:** newly written, public-safe illustration; 13 September 2026. This is not a retained benchmark transcript or a unique correct answer.

**Question:** Design a product for people moving to a new city.

The exchange has already started with `New` and `Candidate`. Candidate mode answers only Stage 0 and then stops.

---

**Stage 0 — Clear communication | 3 min**

### Framing

I’ll treat this as a zero-to-one consumer product. The prompt is broad, so I’ll constrain the environment without choosing a target segment or feature yet.

### Assumptions

- **User:** I’ll begin with adults making a voluntary domestic move rather than refugees, temporary tourists, or employer-managed relocations; those groups have materially different constraints.
- **Market:** I’ll start in one large, English-speaking city and design for expansion once we understand which local data and partnerships matter.
- **Timing:** I’ll focus on the first three months around the move, when people make high-stakes decisions and have not yet built reliable routines or relationships.
- **Product scope:** I’ll consider a mobile-first experience. I won’t assume a marketplace, social network, or AI solution before identifying the user and problem.

### Game plan

I’ll first explain why moving support matters and define a mission. Then I’ll map the relevant ecosystem, choose and segment the person we should serve first, and make that target concrete. I’ll walk through the current moving journey, identify several problems, and prioritize one using severity, frequency, leverage, and solvability. Finally, I’ll compare credible solution mechanisms, select one, and define a focused V1 with distribution, success measures, and key risks.

**Decision:** I’ll explore a mobile-first product for voluntary domestic movers during the first three months around a move, while leaving the target segment and solution open.

### Coaching cues — not spoken

- **Goal:** Define the playing field without prematurely choosing the user, problem, or solution.
- **Key questions:** What kind of prompt is this? Which assumptions make it tractable? What reasoning path will I follow?
- **Watch-out:** Constrain only what matters; do not start solving.

`Frame → Constrain → Preview`
